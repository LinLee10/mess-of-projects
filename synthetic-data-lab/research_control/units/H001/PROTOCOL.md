# H001 calibration and record order experiment

This is a bounded development probe following recovered evidence and the verified R001 checkpoint control. It is not a replacement for the entire research plan. No final holdout is evaluated. Historical large scores are not accepted as baselines. No new external dataset is introduced.

H001a: Stable sorting of ties during marginal calibration can introduce record order dependent values and cross feature structure. Compare identical constant numerical tables before and after reordering their records. The expected failure is a violation of permutation equivariance. Compare legacy tie order, feature specific tie priorities attached to immutable synthetic IDs, and tie preserving midranks. The latter two are standard statistical remedies, not claims of invention. A corrected order rule does not mean a collapsed generator has recovered the true dependencies.

H001b: Global numerical calibration may improve individual columns while worsening class associations relative to real data. On one matched interpolation pool compare no correction, original pooled correction, pooled correction with ID keyed ties, and contextual correction with ID keyed ties. Context means identical cover, wilderness and soil categories. A group specific map uses the label only as generator context; students never receive the target as an input. All mappings fit only real training data. Natural categorical counts remain unchanged.

Use all 348563 eligible Covertype training rows and all 116314 development rows. The compact predictor int64 hash modulo 100 reconstructs the reported counts. Membership is saved; historical byte identity is not claimed. The 116135 reserved rows are not evaluated. Historical holdout exposure is unknown, so this is exploratory development evidence.

One synthetic row is generated per real anchor, with a randomly selected endpoint inside its identical categorical bundle and weight uniform in 0.1 to 0.9. No arbitrary source cap is used. This exact anchor allocation differs from the earlier stochastic anchor draws and is declared. All variants share the same pool and match the real training row count. LightGBM uses 150 trees, 63 leaves, learning rate 0.08, fixed student seed 991 and two threads. Generation seeds are 17, 29 and 41. CPU only. Per seed ceiling 15 minutes, no automatic retries.

Run the 18 new contract controls before fitting. Retain unchanged original tests. Report correct predictions and average per class recall, per class recall itself, per feature KS, class conditional KS, complete table predicate frequencies, training defined tail errors, exact copying and unique counts. A screening benefit is at least one percentage point in mean balanced accuracy, with positive direction for each generation seed, exact copying below one percent and no hard validity loss. Changes in fidelity and rare classes remain separate vetoes, not averaged away. No statistical population significance is inferred from three generator seeds. A second learner and neural/statistical reference comparisons are required before promotion.

The legacy correction is checked against the surviving v3 function. Artifact checking is a separate process without imports from the worker. Each completed run retains full synthetic tables, input membership, generation lineage, models, probabilities, metrics and source. GitHub upload and full readback verification are required before it is marked durable. A real source score, a calibration counterexample and a model gain are three different claims.
