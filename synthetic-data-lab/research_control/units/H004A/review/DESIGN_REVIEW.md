# H004A independent preimplementation design review

Verdict: the protocol can support a bounded empirical mechanism diagnosis on the frozen training contexts, conditional on its execution and independent verification gates. It can determine whether measured bandwidth selection improves the specified nearest distance diagnostic compared with the frozen heuristic under the registered audit seeds. It cannot establish a general nearest distance law, downstream utility, privacy, or synthesis promotion. No implementation or measurement result was available to this review, and no acceptance of an implementation or experimental outcome is issued here.

## Concrete risks and required interpretation

1. Exact marginal assignment changes geometry after latent sampling. The beta variance ratio is a conditional latent variance identity, not a law for nearest distances. Preserve the paired inverse empirical CDF control and anchor displacement measurements so postprocessing effects remain distinguishable from latent smoothing effects.
2. Response need not be monotone in bandwidth. Beta rejection sampling means matched RNG initialization does not imply monotone common random numbers. Evaluate every unique clipped candidate, preserve failed and nonmonotonic curves, and select by the registered objective with exact smallest width ties. Do not interpolate or extend the grid after observing outcomes.
3. Median improvement can conceal tails, copying, dependence, or sparse context damage. Candidate Q and the five quantile tables help diagnose this but do not eliminate it. Preserve KS, lower tail fractions, exact duplicates, zero distances, Spearman errors, class strata and remaining context reports even when the median screen passes.
4. Row identity matters twice: frozen identity keyed rank ties and leave one out exclusion. Duplicate rows are distinct observations with legitimate zero leave one out distances. Excluding equal values would inflate the target and could manufacture apparent improvement. Deduplicating reference rows or reassigning identities also changes the experiment.
5. A zero target median is a declared degenerate policy. Validate all inputs before selecting the smallest width; keep singleton and constant contexts in accounting. Positive but tiny target medians can amplify normalized errors, so retain raw targets and errors beside normalized summaries. Do not silently replace the denominator or remove contexts.
6. Clipping and repeated settings reduce the effective grid, and a boundary winner is evidence about the registered grid only. Record original and clipped settings, unique widths and boundary selections. The primary n >= 100, positive median population requires exact row coverage and count weighting. Equal context weighting answers a different question.
7. Calibration and audit separation is essential. Hash and persist selections before any audit generation, reconstruct both objectives independently from retained calibration measurements, and enforce the every audit seed screen. Two calibration seeds and three audit seeds do not establish a population confidence interval. No replacement seeds, reserved data, or audit guided reselection are justified.
8. Atomic JSON protects each individual file, not completeness of an entire run. Require a final completeness record tied to input identities, source identities, selected widths, all contexts and all seeds. Partial contexts and resource failures remain partial evidence; a parseable JSON file alone is insufficient. Serialization and overwrite behavior are tested here, while interruption and full run completeness require the registered fixture and execution gates.
9. Full coverage exact nearest neighbor work can stress the resource ceilings. No cap or approximate neighbor fallback is authorized. Independent verification must use a different nearest neighbor implementation on retained postassignment arrays. This test suite uses direct scalar distance calculations on synthetic fixtures, which establishes a local correctness oracle but does not certify full data execution, performance or artifacts.

## Contract tests and limitations

`test_mechanism_contract.py` contains 41 collected cases by static parameter expansion. Expectations come from contract arithmetic, synthetic fixtures, direct Euclidean distance loops, and the explicitly frozen H002 ordinal and assignment dependencies. It exercises validation, sorted unique clipping, both objectives, nonmonotonic selection, exact ties, zero target validation order, identity sensitive generation, exact marginal multisets, int64 boundaries, deterministic seed/context initialization, inverse empirical CDF mapping, scale invariance, identity exclusion, input preservation, complete output lengths and atomic JSON behavior.

The tests load the exact contracted `src/mechanism.py` with importlib. They deliberately do not skip an absent implementation. The execution record under the checkout's `reviewer_logs/h004a_acceptance` contains source hashes, commands, exits, stdout and stderr. A successful syntax compilation establishes syntax only. Collection failure caused by the absent implementation is an unavailable behavioral check, not a failing implementation result and not permission to create one. No historical scores, real data, future production code, network, training, tool configuration or original test modifications were used.

The smallest sound next step is implementation against the fixed API, followed by these tests and the protocol's prerequisite gates. A favorable distance result would permit consideration of a separately registered utility challenge. It provides no privacy guarantee and cannot substitute for that challenge.
